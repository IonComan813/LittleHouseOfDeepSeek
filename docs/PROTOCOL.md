# 小屋协议

## 伪代码

agent 通过 `house_do` 工具提交一段伪代码，人类可以在 `python -m littlehouse --repl` 里用同样的写法。

```
goto(沙滩); surroundings()
pick_up(shell#1)
goto(客厅)；water_plants(绿萝)        // 全角分号、全角括号也可以
order("番茄种子", 2)
```

- 语句：`动作(参数, ...)`，用 `;`、`；` 或换行分隔；无参数时括号可省略（`surroundings`）。
- 参数：裸词（`厨房`、`pot#1`）、数字、或带引号的字符串（`"..."`、`「...」`、`“...”`）。
- `//` 之后是注释。
- **先检查整段**：只要有一步写的是不存在的动作（拼错、用了别的名字）或参数太多，**整段一步都不执行**。结果里列出每个问题，并附上动作清单（「这里能用的动作：…；其他地方的动作：…」）。**不猜她想写什么**，也从不自动替她换成正确的动作。
- **执行时遇到第一个失败就停下**（比如缺原料、不在对的地方），返回已执行部分的结果，方便重新规划。
- 每段最多 20 条语句、2000 个字符。解释器不会 `eval` 任何东西。
- **只写动作名、不写参数**（`cook`、`plant`、`sell`、`order`、`goto`……）会列出现在能填什么：能做的菜和缺的原料、背包里的种子和空菜地、
  能卖的东西和收购价、目录和价格、能去的地方。结果行用「？」标出，不算失败，后面的步骤照常执行。
- 做不了的动作会说怎么才能做：「这件事要在厨房做，先 goto(厨房)」「团子在卧室……可以 goto(团子) 走过去」「「邮箱」在庭院」「背包里没有「红烧肉」。可以在厨房 cook(红烧肉)」。
  `goto` 除了地点，也接受猫的名字（走到猫身边）和东西的名字（走到它所在的房间）。
- 每段脚本做完，结果末尾有一行「在厨房可以：recipes 看菜谱、cook 做菜……；可去：客厅」，列出当前位置能用的动作和简短说明。
- `surroundings()` 里「这里能做」一行按当前位置和状态列出动作名（例如厨房：recipes、cook、eat、clean），另附随时能做的动作。
- **动作花真实的时间（M3）。** 一段脚本由小屋里的执行器（`house/littlehouse/tasks.py`）按游戏时钟一步步播放：
  走路按路程，做饭、打扫、钓鱼都要真的等那么久。`house_do` 等整段做完才给出结果。

结果格式（每步一行标题 + 时间 + 缩进的描述；最后是期间发生的事和剩余时间）：

```
✓ goto(沙滩)  [08:03]
  你穿过庭院，来到了沙滩。
✓ fish()  [08:03–08:05]
  钓到了一条鲈鱼！
✗ pick_up(海星)  [08:05]
  这里没有「海星」。
期间：灶台上的萝卜汤炖好了。
现在 08:05，自由活动还剩 27 分钟（到 08:32）
```

### 动作时长

时长都在 `content.py` 里（`ACTION_SECONDS`、`RECIPES` 等），目标是「一圈想做的事」大约二十分钟。

| 动作 | 时长 | 说明 |
| --- | --- | --- |
| 走路 | 按路程，1 格 / 秒 | 和画面上走的完全一样（穿过门口）；相邻房间约 10 秒，卧室到沙滩约 25 秒。房间里走到要用的东西旁边也算 |
| `surroundings` `help` `inventory` `recipes` | 0 | |
| `examine` `call_cat` | 5–10 秒 | |
| `water_plants` `pick_up` `harvest` | 第一个 15 / 10 / 40 秒，之后每个 10 / 8 / 30 秒 | 挨个走过去做；做到一半被打断，剩下的没做 |
| `open` `put_on_shelf` `feed_cat` `stroke_cat` `catalog` `order` `sell` | 20–40 秒 | |
| `plant` `place` `stow` | 40–60 秒 | |
| `eat` | 做好的菜 2 分钟，即食食品 1 分钟，零嘴 45 秒 | 在厨房会坐到木桌边 |
| `cook` 炒、煎 | 1–2 分钟，**一直守着** | 中途被打断（走开）菜会糊 |
| `cook` 拌 | 1 分钟 | 在台面上做，不占灶眼 |
| `cook` 煮饭、炖、蒸、烧、包饺子 | 先忙 30 秒–3 分钟，再**自己熟** 3–5 分钟 | 下锅后可以去做别的；好了以后她在厨房（或回到厨房）时自动盛出来；灶台两个灶眼 |
| `clean(分钟)` | 脏度 ÷ 25 分钟（最脏 4 分钟，最少 20 秒） | 进度保留在脏度里：扫了一半走开，下次只要扫剩下的；`clean(2)` 只扫两分钟 |
| `fish` | 每一竿 1–3 分钟（随机） | 被打断就什么也没钓到 |
| `wait(分钟)` | 最多 30 分钟 | `wait()` 等到灶台上下一道菜好 |

### 菜谱（地道家常菜，`content.RECIPES`）

油盐酱醋糖、姜蒜、蚝油、香油默认厨房里有；表里的原料要自己种、钓，或者在订货目录上买。

| 菜 | 原料 | 做法与时间 |
| --- | --- | --- |
| 白米饭 | 大米 | 煮，先忙 30 秒，再自己煮 5 分钟，期间可以走开 |
| 荷包蛋 | 鸡蛋 | 煎，要一直守着，约 1.5 分钟 |

| 蛋炒饭 | 白米饭、鸡蛋、葱 | 炒，要一直守着，约 2 分钟 |
| 酸辣土豆丝 | 土豆×2 | 炒，要一直守着，约 2 分钟 |
| 蒜蓉菠菜 | 菠菜 | 炒，要一直守着，约 1 分钟 |
| 蚝油生菜 | 生菜 | 炒，要一直守着，约 1 分钟 |
| 醋溜白菜 | 白菜 | 炒，要一直守着，约 1.5 分钟 |
| 拍黄瓜 | 黄瓜 | 拌，约 1 分钟 |
| 番茄蛋汤 | 番茄、鸡蛋 | 煮，先忙 1 分钟，再自己煮 3 分钟，期间可以走开 |
| 萝卜炖排骨 | 萝卜、排骨 | 炖，先忙 2 分钟，再自己炖 5 分钟，期间可以走开 |
| 南瓜小米粥 | 南瓜、小米 | 煮，先忙 1 分钟，再自己煮 5 分钟，期间可以走开 |
| 清蒸鲈鱼 | 鲈鱼 | 蒸，先忙 1.5 分钟，再自己蒸 4 分钟，期间可以走开 |
| 干煎小黄鱼 | 小黄鱼 | 煎，要一直守着，约 2 分钟 |
| 红烧鱼 | 任意一条鱼 | 烧，先忙 2 分钟，再自己烧 4 分钟，期间可以走开 |
| 葱油饼 | 面粉、葱 | 煎，要一直守着，约 2 分钟 |
| 白菜猪肉饺子 | 面粉、猪肉馅、白菜 | 包，先忙 3 分钟，再自己煮 3 分钟，期间可以走开 |

**打断。** 新的脚本到达（REPL 里又输入了一段）、DSH 里中止了这一轮，都会打断正在做的那一步，
由那一步自己决定做到一半意味着什么（见上表），后面的步骤丢弃。
**自由活动时间到了不打断**正在做的那一步（做完为止），只是不再开始脚本里后面的步骤；有开了头的事没做完时会顺延（见「时间到了还没做完」）。

### 动作（M1.5）

很多动作的参数可省略：省略时作用于当前位置所有合适的东西（`water_plants()` 浇这里所有植物和菜地，`pick_up()` 捡起这里所有东西，`harvest()` 收获这里所有熟了的作物，`put_on_shelf()` 把所有收藏品摆上架）。

| 分类 | 动作 | 说明 |
| --- | --- | --- |
| 观察 | `surroundings()`、`help()`、`examine(东西)`、`inventory()` | `surroundings()` 看看四周，里面有「这里能做」 |
| 移动 | `goto(地点)` | 自动寻路：客厅、厨房、卧室、庭院、沙滩 |
| 自己 | `eat(食物)`、`wait(分钟)` | 会饿（没有精力 / 疲劳这一项）；想等就 `wait` |
| 厨房 | `recipes()`、`cook(菜名)`、`wait()` | 菜谱见上表；偶尔做焦（累的时候更容易），偶尔格外好吃 |
| 家务 | `clean()`、`tidy_mess(乱子)`、`place(家具)`、`stow(家具)`、`water_plants(植物)` | `clean` 是平常的打扫（扫掉落的灰，房间里有乱子会先收拾），`tidy_mess` 只收拾团子闯的祸；房间会随时间落灰；打扫时偶尔在角落里有发现（越脏越可能）；家具要自己买，`place` 摆在当前房间（和收藏架无关） |
| 庭院 | `open(邮箱)`、`open(包裹)`、`plant(种子, 菜地)`、`harvest(菜地)` | `open(邮箱)` 一次取出所有信并读给她（读过的信不保留），`open(包裹)` 拆门口的快递；作物要浇水、看季节，收成有多有少 |
| 买卖 | `catalog()`、`order(物品, 数量)`、`sell(物品, 数量)` | 在屋里翻目录下单，中午 12 点以前下单当天下午送到门口，之后下单第二天下午送到；在庭院把东西放进寄售箱，下午快递来的时候收走入账。**一贝币的购买力约等于一元人民币**：鸡蛋 1/个、大米 3/斤、五花肉 9/半斤、台灯 59；开拓署按略低于零售的价格收购作物、鱼和海边捡的东西（鲈鱼 18、粉色海螺 6），不收做好的菜。目录里也有**即食食品**：饭团 6、三明治 9、面包 5、即食便当 16、酸奶 4、苏打饼干 5，拆开就吃（约 1 分钟），不用每次自由活动都做饭 |
| 沙滩 | `pick_up(东西)`、`fish()`、`open(漂流瓶)` | 雨天贝壳和鱼更多；打雷不能钓鱼；漂流瓶捡到或钓到后在背包里，`open(漂流瓶)` 读里面的纸条（在哪都行） |
| 海边 | `play_in_water()` | 在沙滩上玩水、踩浪 1–2.5 分钟（打雷不行）。结果（`actions.wade_text`）依次是：**水温**（`content.WATER_FEEL`：按季节；**晴天的中午到傍晚（12–19 点）浅水是温的**，其他时候凉，冬天冰；小雨、小雪另有一句）、**玩水或脚下的感觉**（`BEACH_PLAY`：踩浪、脚陷进软软的淤泥、沙子从脚趾缝流走、鹅卵石、海草缠脚踝……）、**有时有小鱼游过来**（`SHALLOW_FISH`：鱼和动作分开随机，按季节；夏天约一半，冬天少；天黑看不清，只觉得有东西擦过小腿，晴天满月的晚上看得见）、**海面上的光**（清早朝阳、白天阳光、傍晚夕阳；晚上**不说月相**，只说月光的效果：晴天「月光落在海面上」、多云「月亮躲在云后面」、没月亮黑黑的，**满月**多写几句：一条亮路铺到脚边、湿沙上照出影子）。日常里的「在海边玩水」用同一段文字。**画面**：她站在沙滩最靠海的一排（`scene.STANDS["shore"]`），脚边溅起水花；文字里有看得见的小鱼时，海里画一小群鱼围着她的脚打转（不分种类；结果在开始玩水时就定下，所以玩的过程中画面和最后的文字一致；日常里只有被问到、小结果里有鱼时才画） |
| 夜空 | `look_at_sky()` | 天黑以后（19 点起）在庭院或沙滩看 2–4 分钟。**月相按真实日期算**（`house/littlehouse/sky.py`：从已知的新月起按朔望月推算，月出每天晚约 50 分钟，所以能说出「天上挂着蛾眉月」「下弦月还没升起来」）；四季的星空不同；下雨 / 阴天什么也看不见，多云只能从云缝里看。**流星**：平时约 12%，真实的流星雨极大夜（英仙座 8/11–13、双子座 12/13–15、象限仪座、狮子座……）约 85% 且一次好几颗；云多、满月时少见。**其他随机小事**（`content.SKY_EVENTS`）：人造卫星、夏天院子里的萤火虫、夏秋海边的夜光藻、远处渔船的灯火、夜鸟、月晕（预示变天）、团子跟出来一起看。日常里天黑后不下雨的晚上，她有时也会自己「坐在院子里看星星」 |
| 收藏 | `put_on_shelf(收藏品)` | 把捡到的贝壳之类摆到客厅的收藏架上（家具用 `place`） |
| 猫 | `call_cat()`、`feed_cat(食物)`、`stroke_cat()`、`play_with_cat(玩具)`、`goto(团子)` | 团子会饿、会在屋里到处走（刚和它玩过、喂过、摸过的 10 分钟里不走）；亲密度影响叫不叫得动；每天的脾气不同（黏人 / 平常 / 傲娇 / 烦躁）。`play_with_cat` 1–2 分钟：玩具可选（逗猫棒、小铃铛球、猫薄荷玩偶、毛线球可以订购；拆包裹会留下纸箱），它玩得开心 / 一般 / 没兴趣取决于当天脾气、饿不饿、刚玩过没有、是不是它最喜欢的玩具，还会随机发生和房间有关的事（跳上沙发、从木桌上跌下来、撞翻盆栽弄脏地板……）。**留下的乱子**（撒了一地的土、洒了一地的水、掉在地上的书 / 订货目录 / 靠垫、被踩乱的被子）是房间里的东西：`surroundings()` 里看得到、画面上画得出，`tidy_mess()` 或 `clean()` 收拾（5–15 秒一处），盆倒了要先扶起来才能浇水。没人看着的时候团子大约每天闯一次祸（脾气烦躁或饿的时候更多），会出现在「这段时间里」 |

物件可以用编号（`pot#1`）或名字（`绿萝`）指代；背包物品、目录商品、房间里的东西、菜名**都要写全名**。写的东西找不到时不执行，也不猜，而是列出能写的全名：「这里没有「菜地」。这里有：绿萝、菜地1……」「背包里没有「萝卜」。背包里有：萝卜种子×2……」「目录里没有「番茄种」。目录上有：……」「菜谱里没有「煎蛋」。要写菜谱上的菜名：……」。东西在别的房间时说在哪（「「邮箱」在庭院，不在这里。先 goto(庭院)」）。


## 自由活动与平淡的日常（M3）

每天有几段**自由活动时间**（插件配置 `wake.slots`，默认早上 7:30–8:30、中午 11:30–12:30、傍晚 17:30–18:30、晚上 21:30–22:30 之间随机开始，
各 40 分钟）。这段时间由模型决定她做什么。

**时间到了还没做完**：到点时如果她正在做一件事，或者有开了头、成套的事没做完——灶台上的菜、这次做好还没吃的菜、团子弄乱的东西（`world.unfinished()`）——
自由活动**顺延**（最多 30 分钟，`POST /session {overtime: true}`）：小屋只接受做完这些的动作（`goto`、`wait`、`tidy_mess`、`eat(这次做的菜)` 和看看四周），其他的会被拒绝；
写日记、发消息、`end_free_time` 随时可以。每段结果末尾告诉她还剩什么没做完；都做完了提示她 `end_free_time`。她停下不再行动时加时也就结束。

**睡觉和起床**：她在 23:30–24:00 之间随机的一分钟睡觉（插件配置 `sleep`），在第一段自由活动开始时醒来——所以每天发给她的第一条消息就是早上的自由活动。
睡觉时插件发一条「该睡觉了」，让她睡前用 `diary_read` / `diary_write` / `diary_edit` 整理当天的日记；小屋里她躺到床上（`POST /session {asleep: true}`）。
睡着期间 QQ 消息一律不交给她（自动回 `qq.sleepReply`，同一个聊天半小时最多一次）。

其余时间她**过平淡的日常**，由小屋自己安排（`content.IDLE_ACTIVITIES`）：每小时挑一件，走过去待着。**不安排她答不上细节的事**（比如「看书」看的什么书）：
收拾屋子擦擦桌子（去最干净的房间——真正脏的留给她自己）、陪团子玩（跟着团子走）、在海边玩水踩浪、在礁石边钓鱼（要有鱼竿、不打雷）、晚上坐在院子里看星星、
窗边发呆、在木桌边喝茶、午后睡午觉、树下晒太阳、沙滩散步、看夜里的海。睡着的时候在床上睡觉。
其中收拾屋子（`clean()` / `tidy_mess()`）、陪团子玩（`play_with_cat()`）、玩水（`play_in_water()`）、钓鱼（`fish()`）、看星星（`look_at_sky()`）自由活动里她也能自己做。
**这些都不改变世界，也不记录**：没人找她，就当没发生过。只有消息把她叫醒时，才按她此刻在做的事临时生成一个小结果（`world.idle_story()`，同一件事里保持不变）一起告诉她：
陪团子玩 → 团子的反应（按当天的脾气）、在海边玩 → 浪花打湿了裙摆之类 + 海面上的光、钓鱼 → 浮漂没动 / 小鱼放回海里之类（不会真的钓到）、
沙滩散步 / 看夜里的海 → 海面上的光、看星星 → 和 `look_at_sky()` 一样的夜空；收拾屋子之类没什么可说的，就只说在做什么。
这段时间里她不会饿过「有点饿」（饥饿上限 60）。

### 世界随时间的变化

| 什么 | 规则 |
| --- | --- |
| 她自己 | 饥饿 +5/小时；自由活动以外饥饿最多 60（她自己随便吃点东西） |
| 盆栽 / 菜地 | 水分每天 −30 / −50；下雨时菜地自动浇透 |
| 作物 | 浇过水且在适合的季节时才生长；成熟后产生「成熟了」的消息 |
| 房间 | 每天落灰 +6；猫所在的房间多一些；做饭让厨房 +8 |
| 团子 | 饥饿 +4/小时，到 80 时发出「喵喵叫」的消息；亲密度每天 −2；大约每小时换一个房间 |
| 开拓署 | 每周一随快递送来基本补给（大米、鸡蛋、猫粮、牛奶）和一封信；新存档有一封欢迎信讲清楚规则 |
| 快递 | 没有名字，也不和她打交道：每天下午 14:00–16:30 之间随机一个时间来一次（`world.courier_time`，同一天固定；她这时通常不在自由活动），把到期的订单、每周一的补给和开拓署的信放在门口 / 邮箱里（没有别的随机来信），同时收走寄售箱、按收购价付贝币。**包裹和信不算「这段时间里」的新闻**；只要门口有包裹没拆、邮箱里有信没看，每次自由活动开始时单独说一句（`/status` 的 `waiting`：「门口有快递（3 件东西）还没拆；邮箱里有 1 封信还没看。」），一般是傍晚那段第一次说 |
| 小事件 | 大约每两天一件，在早上 7 点（起雾、海鸥、浮木冲上岸……），进入「这段时间里」 |
| 沙滩 | 每天约 2 件（雨天 4 件）新东西冲上岸，最多 4 件 |

离开很久时最多补算 14 天。

## HTTP 接口

小屋进程只监听 `127.0.0.1`，启动时把 `{port, token, pid}` 写进 `<状态目录>/house.json`。
除 `/health` 外，所有请求都要带 `X-House-Token`；`Host` 必须是 `127.0.0.1` 或 `localhost`（防 DNS rebinding）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | `{ok, version, pid}`，无需令牌 |
| GET | `/look` | `{ok, text}` |
| GET | `/help` | `{ok, text}` |
| GET | `/events?since=…&actor=resident` | 事件（可按时间、角色过滤，最多 50 条）；唤醒时用来生成「上次醒着的时候，你……」 |
| GET | `/news?since=YYYY-MM-DDTHH:MM:SS` | 这之后「世界自己发生」的事（最多 20 条），用于唤醒时告诉她「你不在的时候」 |
| GET | `/state` | 完整世界状态（JSON） |
| GET | `/status` | `{free, free_until, busy, doing, idle, location, waiting}`：是否在自由活动、正在做什么、平时在做什么、门口 / 邮箱里还有什么没看（`POST /session` 也返回这些） |
| GET / POST | `/window` | 查看 / 打开关闭动画窗口：body `{open: bool, scale?: 1-4}`（没有 pygame-ce 时 501） |
| GET | `/screenshot?scale=1\|2` | 当前画面的 PNG（需要 pygame-ce，否则 501），同时存一份到 `world/latest.png` |
| POST | `/do` | body `{script, wait?}` → `{ok, done, id, text, results[]}`：按真实时间执行，最多等 `wait` 秒（默认 900）；没做完时 `done=false`，脚本继续执行 |
| POST | `/report` | body `{id, wait}` → 同上：接着等编号为 `id` 的脚本（插件每次最多等 240 秒，避开 Node fetch 的 5 分钟限制） |
| POST | `/interrupt` | 打断她正在做的事（DSH 中止这一轮时调用） |
| POST | `/session` | body `{free_until}`（epoch 秒；0 = 结束）→ 开始 / 结束自由活动；返回 `before`（她之前在做的日常） |
| POST | `/shutdown` | 存档并退出 |

POST 需要 `Content-Type: application/json`，body 上限 16 KB。

| 文件 | 内容 |

| `qq/YYYY-MM-DD.jsonl` | 当天所有 QQ 消息（收到的、她发的），一行一条（`chat`、`name`、`text`、`out`） |
| `transcripts/YYYY-MM-DD.jsonl` | 当天会话的全文（消息、她写的话、工具调用和结果）：长期记忆的原料，关着时只是留底 |
| `qq-contacts.json` | 给她发过消息的人（名字 → QQ 号），`phone_message(to)` 用 |
| `qq-requests.json` | 还没处理的好友请求 |
| `memory/memory.json` | 长期记忆（`memory.enabled`，默认关）；`memory/memory.md` 是给人看的样子；`memory/archive.jsonl` 存所有记过的条目（不会忘） |

## 日记工具

由 `dsh-little-house/diary` 提供。她醒着的时候（自由活动、回消息、睡前）随时能用：

| 工具 | 说明 |
| --- | --- |
| `diary_write(entry)` | 往今天的日记里追加一段（最多 2000 字）：**每调用一次就是一段**，标题是写的时间和时段（`### 08:35 · 小屋 · 早上`，自由活动以外只有「小屋」） |
| `diary_edit(time, text)` | 改今天某一段（按标题里的时间找）；text 为空就删掉这一段。规则里引导她先 `diary_read()` 看今天的内容和每段的时间，再改；也可以先随手写，睡前再整理 |
| `diary_read(day?)` | 读某天的日记：今天 / 昨天 / 前天 / YYYY-MM-DD，以前哪天都可以 |
| `end_free_time()` | 结束这次自由活动。这次还没写日记时，第一次调用只**问**她要不要写日记、要不要给主人发消息，再调用一次就结束（不强制）；时间到了她却停着时，插件会发一句「想写日记的话现在写，然后 end_free_time」 |
| `end_errand()` | 自由活动以外接管角色做完事后，把角色交还给日常 |

## 一天一个会话

每天一个「小屋生活 · 日期」会话，0 点换天（`session.rolloverHour`）：**当天的几段自由活动、手机上的 QQ 私聊、睡前整理日记都在这一个会话里**；第二天开新的。
插件发给她的消息都用 `agent.steer`：她空闲时开一轮，正在忙（自由活动做到一半、或在回消息）时在下一步插进去。

- **系统提示词**：人设的第一段（简短版）+ 小屋规则。人设文件里的 `<!-- -->` 注释不给她看。
- **每天的第一条消息**（通常就是早上醒来的那条）开头是：日期、「## 你是谁」（完整人设）、「## 昨天的日记」（见下「记忆」），再接着是这条消息本身。
- 日记、QQ 记录也按同样的「天」划分。

## 手机与 QQ（M5）

她的背包里一直有一部**手机**（`content.PHONE`）：不能吃、卖、摆、喂，`examine(手机)` 能看。QQ（以后还有上网）就是她用这部手机做的事。

插件直接连 NapCat 的 OneBot 11 **WebSocket 服务端**（`qq.url`，正向连接，`plugin/lib/onebot-client.js` + 自带的极简 WebSocket 客户端 `lib/ws-client.js`，不走代理），断线自动重连。

| | |
| --- | --- |
| 谁能找她 | 私聊：主人（`ownerQQ`），和 `others`：默认**她（NapCat 登录的那个 QQ 账号）的好友**都可以（`friends` = 好友都行；`listed` = 只有 `friends` 列的 QQ 号；`none` = 只有主人）；不是好友的临时会话不收。她醒着的时候都可以。**群聊暂时关掉**（代码以注释保留在 `qq.js`） |
| 收到的消息 | 进当天的会话：「（手机响了，是 QQ 消息：）主人：……」，别人是「主人的朋友阿青：……」（名字取好友备注或昵称；好友请求里还不是朋友，不这样叫）；自由活动以外，开头告诉她角色此刻在做什么（「11:27，不是自由活动时间。你的角色此刻在客厅，坐在大窗边发呆。手机响了……」）。QQ 表情写成 `[表情:微笑]`，图片写成 `[图片]` 并把图片本身附在消息后（存为 DSH 附件，每条最多 4 张；她看得见），表情包 `[表情包]`。**语音、视频、文件、聊天记录、卡片在桥这里就挡掉**，不发给模型（只记进 QQ 记录）；只有这些内容的消息不会叫她 |
| 她回消息 | 只用 `phone_message(text, photo?, to?)`：text 就是发出去的话（空行分成几条，`[表情:名称]` 变回 QQ 表情，名字不对就原样当文字；去掉 Markdown），`photo` 附一张小屋现在的照片，`to` 不写就是主人，回朋友写朋友的名字（给她发过消息的人记在 `qq-contacts.json`）。**她直接写的文字不会发出去**。条数不限 |
| 自由活动以外 | 她回消息时可以 `house_do` 看看四周（`surroundings()`、`inventory()`、`help()`：`POST /do {look_only: true}`，马上回答，不打断日常）。**主人或朋友请她在屋里做事时**，她直接用 `house_do` 去做：别的动作会让小屋返回 `needs_control`，插件就让她**接过角色的控制权**（小屋进入和自由活动一样的状态，最多 `control.maxMinutes` = 30 分钟），做完她调用 **`end_errand()`** 把角色交还给日常；忘了调用的话，这一轮结束时或时间到了自动交还。睡前那一轮不能接管 |
| 主动发消息 | 自由活动里随时可以；`end_free_time` 第一次调用时也会问她（只发有趣、重要的事，流水账不发；不强制）。发出的消息就在当天的会话里，不用另外告诉她 |
| 好友请求 | 有人加她（NapCat 登录的账号）为 QQ 好友：她收到「（手机响了，是一条好友请求：）小林（QQ 789）想加你为好友，验证消息：……」，规则让她先用手机问主人；主人回复后她用 `phone_friend_request(qq, accept)` 接受或拒绝（`set_friend_add_request`）。睡着时来的请求，第二天早上醒来的消息里告诉她（`qq-requests.json`） |
| 答应别人的事 | 规则里告诉她：自由活动以外她只在有消息时醒来，没法「待会儿」自己去做，所以请对方晚点再提醒她（像平常聊天那样说，不提「自由活动」）；自由活动里估计在结束前做得完才答应。自己想以后做的事可以写进日记 |
| 睡着的时候 | 从睡觉到第二天醒来，消息一律不交给她，自动回 `qq.sleepReply`（默认「（睡着了……zzZ）」，同一个聊天半小时最多一次；留空 = 不回） |
| 记录 | 收到的、她发的，都追加到 `qq/日期.jsonl`（长期记忆打开时是它的原料） |

## 记忆：她记得的就是昨天的日记

**默认没有长期记忆。** 每天第一条消息里放**前一天的日记全文**（「## 昨天的日记（你记得的事主要就是这些。更早的日记可以用 diary_read(日期) 翻看。）」；
前一天没写就放最近一次写的那天，标题写日期；超过 `memory.diaryChars`（默认 6000 字）只放后面的部分，睡前整理的那段一定在）。
睡前「该睡觉了」的消息提醒她：明天醒来记得的主要就是今天的日记，想做的事、答应别人的事、重要的事和心情要写进去。规则里也这么说。
这样她只记得最近一两天写下的事：小屋里的日子对她一直是新鲜的；想记得更久，要她自己翻日记。

### 长期记忆（M4，可选，`memory.enabled: true` 打开）

打开后，每天开头放的是下面整理出来的记忆，而不是昨天的日记。这套没有做过长时间的压力测试。


**原料**：当天的日记（她自己挑的重要的事）+ **当天会话的全文**（插件边发生边记进 `transcripts/日期.jsonl`：发给她的消息、她写的话、每次工具调用和结果的前 400 字；不含她的思考过程和开头的人设、记忆）。QQ 聊天、她答应别人的事都在会话里。没有会话记录的旧日子退回用 `qq/日期.jsonl`。

**整理**：0:10（她已经睡了；以及 DSH 启动时补上还没整理的、最多 7 天），插件开一个「记忆整理 · 日期」会话（preset `little-house-memory`：**不带人设、没有工具**），给它她现有的记忆（带编号）、那天的日记和 QQ 记录，让它只回一个 JSON：

| 字段 | 内容 |
| --- | --- |
| `summary` | 这一天：先写最重要的事和心情，篇幅允许的话平凡的日常也写一些（四到八句，最多 600 字）→「最近的日子」（最近 7 天） |
| `plans` | **想做的事、打算、没做完的事**（日记和聊天里提到的都要列）→「想做的事」 |
| `memories` | **重要、不能忘的事**：和别人的长期约定、小屋生活中很重要的大事、给自己立下的 flag 等等（大多数日子 0 条，最多 3 条，重要度 80–100）→「记得的事」。平常的事放在 summary 里 |
| `people` | TA 的身份或职业（只写提到过的）、喜好和习惯、最近和 TA 有关的事（不超过四件，新的逐渐替换旧的；身份和喜好、习惯随实际情况更新）→「认识的人」。不写「印象」这种主观判断 |
| `recalled` / `done` | 这天又想起的旧记忆（重新变清楚）/ 已经做到的「想做的事」（删掉） |

**淡忘**（`plugin/lib/memory.js`，纯代码，不调模型）：按「上次想起」到今天的天数一档一档变：清晰（2 天内）→ 清楚 → 模糊（只剩前六成，「……（记不太清了）」）→ 只剩印象（前十个字）→ 忘记。重要的记得久：重要度 40 的事约 10 天变模糊、40 天忘记；**想做的事忘得快一倍**；重要度 ≥ 90 的永远不会忘（最多模糊）。忘掉的不再给她看，但都留在 `memory/archive.jsonl`。

**使用**：每天会话的第一条消息开头（「## 你的记忆」，四个小节），最多 `memory.maxChars`（默认 6000）字——超了先少放几天前的日子，再少放想做的事和记得的事。字是字符数（中文大约一字一 token 多一点）。整理后的样子也写进 `memory/memory.md`，方便你看。

## 画面

两种方式，同一个渲染器（`house/littlehouse/render.py`，pygame-ce；大部分画面用 LPC 素材，她由 LPC 角色图层拼成再加上鲸鱼的部分，见 `house/littlehouse/assets/lpc/CREDITS.md`；素材文件缺失时退回代码绘制），都在**小屋进程内**：

| 方式 | 什么时候渲染 | 画面 |
| --- | --- | --- |
| 静态「拍照」 | 只在她 `house_photo`、`phone_message(photo: true)` 或 `GET /screenshot` 时渲染一帧 | 此刻的真实状态：走到一半就画在半路，在灶台边炒菜就有热气 |
| 动画窗口 | 只在窗口打开时（`view.bat`、`POST /window`、配置 `house.window`） | 同上，每一帧都是当时的状态；无人走动时降到 4 fps |

M3 以后动作本身就花真实时间，所以画面不再需要「回放」：`anim.current_pose(world)` 读执行器当前的阶段
（走路就按 1 格 / 秒沿路线插值，做事就画对应的特效），自由活动以外画她正在做的日常（看书、睡觉……）。
灶台上有菜在炖时会一直冒热气。

`house_photo` 给模型的是 1280×872 的 PNG（DeepSeek 计约 600 token）。工具说明里提示她本机算力有限、偶尔看一眼即可。
