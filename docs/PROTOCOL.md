# 小屋协议

## 伪代码

agent 通过 `house_do` 工具提交一段伪代码，人类可以在 `python -m littlehouse --repl` 里用同样的写法。

```
goto(沙滩); surroundings()
pick(shell#1)
goto(客厅)；water(绿萝)        // 全角分号、全角括号也可以
say("今天的海很安静")
```

- 语句：`动作(参数, ...)`，用 `;`、`；` 或换行分隔；无参数时括号可省略（`look`）。
- 参数：裸词（`厨房`、`pot#1`）、数字、或带引号的字符串（`"..."`、`「...」`、`“...”`）。
- `//` 之后是注释。
- **先检查整段**：只要有一步写的是不存在的动作（拼错、用了别的名字）或参数太多，**整段一步都不执行**。结果里列出每个问题，并附上动作清单（「这里能用的动作：…；其他地方的动作：…」）。**不猜她想写什么**，也从不自动替她换成正确的动作。
- **执行时遇到第一个失败就停下**（比如缺原料、不在对的地方），返回已执行部分的结果，方便重新规划。
- 每段最多 20 条语句、2000 个字符。解释器不会 `eval` 任何东西。
- **只写动作名、不写参数**（`cook`、`plant`、`sell`、`order`、`goto`……）会列出现在能填什么：能做的菜和缺的原料、背包里的种子和空菜地、
  能卖的东西和收购价、目录和价格、能去的地方。结果行用「？」标出，不算失败，后面的步骤照常执行。
- 做不了的动作会说怎么才能做：「这件事要在厨房做，先 goto(厨房)」「团子在卧室……可以 goto(团子) 走过去」「「邮箱」在庭院」「背包里没有「红烧肉」。可以在厨房 cook(红烧肉)」。
  `goto` 除了地点，也接受猫的名字（走到猫身边）和东西的名字（走到它所在的房间）。
- 每段脚本做完，结果末尾有一行「在厨房可以：recipes 看菜谱、cook 做菜……；可去：客厅」，列出当前位置能用的动作和简短说明。
- `surroundings()` 里「这里能做」一行按当前位置和状态列出动作名（例如厨房：recipes、cook、eat、clean），另附随时能做的动作。
- **动作花真实的时间（M3）。** 一段脚本由小屋里的执行器（`house/littlehouse/tasks.py`）按游戏时钟一步步播放：
  走路按路程，做饭、打扫、钓鱼都要真的等那么久。`house_do` 等整段做完才给出结果。

结果格式（每步一行标题 + 时间 + 缩进的描述；最后是期间发生的事和剩余时间）：

```
✓ goto(沙滩)  [08:03]
  你穿过庭院，来到了沙滩。
✓ fish()  [08:03–08:05]
  钓到了一条鲈鱼！
✗ pick(海星)  [08:05]
  这里没有「海星」。
期间：灶台上的萝卜汤炖好了。
现在 08:05，自由活动还剩 27 分钟（到 08:32）
```

### 动作时长

时长都在 `content.py` 里（`ACTION_SECONDS`、`RECIPES` 等），目标是「一圈想做的事」大约二十分钟。

| 动作 | 时长 | 说明 |
| --- | --- | --- |
| 走路 | 按路程，1 格 / 秒 | 和画面上走的完全一样（穿过门口）；相邻房间约 10 秒，卧室到沙滩约 25 秒。房间里走到要用的东西旁边也算 |
| `look` `help` `inventory` `recipes` | 0 | |
| `examine` `say` `call` | 5–10 秒 | |
| `water` `pick` `harvest` | 第一个 15 / 10 / 40 秒，之后每个 10 / 8 / 30 秒 | 挨个走过去做；做到一半被打断，剩下的没做 |
| `open` `read` `display` `feed` `pet` `catalog` `order` `sell` | 20–40 秒 | |
| `plant` `place` `stow` | 40–60 秒 | |
| `eat` | 做好的菜 2 分钟，即食食品 1 分钟，零嘴 45 秒 | 在厨房会坐到木桌边 |
| `cook` 炒、煎 | 1–2 分钟，**一直守着** | 中途被打断（走开）菜会糊 |
| `cook` 拌 | 1 分钟 | 在台面上做，不占灶眼 |
| `cook` 煮饭、炖、蒸、烧、包饺子 | 先忙 30 秒–3 分钟，再**自己熟** 3–5 分钟 | 下锅后可以去做别的；好了以后她在厨房（或回到厨房）时自动盛出来；灶台两个灶眼 |
| `clean(分钟)` | 脏度 ÷ 25 分钟（最脏 4 分钟，最少 20 秒） | 进度保留在脏度里：扫了一半走开，下次只要扫剩下的；`clean(2)` 只扫两分钟 |
| `fish` | 每一竿 1–3 分钟（随机） | 被打断就什么也没钓到 |
| `wait(分钟)` | 最多 30 分钟 | `wait()` 等到灶台上下一道菜好 |

### 菜谱（地道家常菜，`content.RECIPES`）

油盐酱醋糖、姜蒜、蚝油、香油默认厨房里有；表里的原料要自己种、钓，或者在订货目录上买。

| 菜 | 原料 | 做法与时间 |
| --- | --- | --- |
| 白米饭 | 大米 | 煮，先忙 30 秒，再自己煮 5 分钟，期间可以走开 |
| 荷包蛋 | 鸡蛋 | 煎，要一直守着，约 1.5 分钟 |
| 红烧肉 | 五花肉 | 炖，先忙 2 分钟，再自己炖 5 分钟，期间可以走开 |
| 番茄炒蛋 | 番茄、鸡蛋×2 | 炒，要一直守着，约 2 分钟 |
| 蛋炒饭 | 白米饭、鸡蛋、葱 | 炒，要一直守着，约 2 分钟 |
| 酸辣土豆丝 | 土豆×2 | 炒，要一直守着，约 2 分钟 |
| 蒜蓉菠菜 | 菠菜 | 炒，要一直守着，约 1 分钟 |
| 蚝油生菜 | 生菜 | 炒，要一直守着，约 1 分钟 |
| 醋溜白菜 | 白菜 | 炒，要一直守着，约 1.5 分钟 |
| 拍黄瓜 | 黄瓜 | 拌，约 1 分钟 |
| 番茄蛋汤 | 番茄、鸡蛋 | 煮，先忙 1 分钟，再自己煮 3 分钟，期间可以走开 |
| 萝卜炖排骨 | 萝卜、排骨 | 炖，先忙 2 分钟，再自己炖 5 分钟，期间可以走开 |
| 南瓜小米粥 | 南瓜、小米 | 煮，先忙 1 分钟，再自己煮 5 分钟，期间可以走开 |
| 清蒸鲈鱼 | 鲈鱼 | 蒸，先忙 1.5 分钟，再自己蒸 4 分钟，期间可以走开 |
| 干煎小黄鱼 | 小黄鱼 | 煎，要一直守着，约 2 分钟 |
| 红烧鱼 | 任意一条鱼 | 烧，先忙 2 分钟，再自己烧 4 分钟，期间可以走开 |
| 葱油饼 | 面粉、葱 | 煎，要一直守着，约 2 分钟 |
| 白菜猪肉饺子 | 面粉、猪肉馅、白菜 | 包，先忙 3 分钟，再自己煮 3 分钟，期间可以走开 |

**打断。** 新的脚本到达（REPL 里又输入了一段）、自由活动时间到了、DSH 里中止了这一轮，都会打断正在做的那一步，
由那一步自己决定做到一半意味着什么（见上表），后面的步骤丢弃。自由活动结束后不会再开始新的一步。

### 动作（M1.5）

很多动作的参数可省略：省略时作用于当前位置所有合适的东西（`water()` 浇这里所有植物和菜地，`pick()` 捡起这里所有东西，`harvest()` 收获这里所有熟了的作物，`display()` 把所有收藏品摆上架）。

| 分类 | 动作 | 说明 |
| --- | --- | --- |
| 观察 | `surroundings()`、`help()`、`examine(东西)`、`inventory()` | `surroundings()` 看看四周，里面有「这里能做」 |
| 移动 | `goto(地点)` | 自动寻路：客厅、厨房、卧室、庭院、沙滩 |
| 自己 | `eat(食物)`、`wait(分钟)`、`say(内容)` | 会饿（没有精力 / 疲劳这一项）；想等就 `wait` |
| 厨房 | `recipes()`、`cook(菜名)`、`wait()` | 菜谱见上表；偶尔做焦（累的时候更容易），偶尔格外好吃 |
| 家务 | `clean()`、`tidy(乱子)`、`place(家具)`、`stow(家具)`、`water(植物)` | 房间会随时间落灰；打扫时偶尔在角落里有发现（越脏越可能）；家具要自己买 |
| 庭院 | `open(邮箱)`、`open(包裹)`、`plant(种子, 菜地)`、`harvest(菜地)` | 邮箱里是信，门口是快递包裹；作物要浇水、看季节，收成有多有少 |
| 买卖 | `catalog()`、`order(物品, 数量)`、`sell(物品, 数量)` | 在屋里翻目录下单，第二天 9 点后送到门口；在庭院把东西放进寄售箱，18 点后收走入账。**一贝币的购买力约等于一元人民币**：鸡蛋 1/个、大米 3/斤、五花肉 9/半斤、台灯 59；开拓署按略低于零售的价格收购作物、鱼和海边捡的东西（鲈鱼 18、粉色海螺 6），不收做好的菜。目录里也有**即食食品**：饭团 6、三明治 9、面包 5、即食便当 16、酸奶 4、苏打饼干 5，拆开就吃（约 1 分钟），不用每次自由活动都做饭 |
| 沙滩 | `pick(东西)`、`fish()`、`read(漂流瓶)` | 雨天贝壳和鱼更多；打雷不能钓鱼 |
| 收藏 | `display(收藏品)` | 摆到客厅收藏架 |
| 猫 | `call()`、`feed(食物)`、`pet()`、`play(玩具)`、`goto(团子)` | 团子会饿、会在屋里到处走（刚和它玩过、喂过、摸过的 10 分钟里不走）；亲密度影响叫不叫得动；每天的脾气不同（黏人 / 平常 / 傲娇 / 烦躁）。`play` 1–2 分钟：玩具可选（逗猫棒、小铃铛球、猫薄荷玩偶、毛线球可以订购；拆包裹会留下纸箱），它玩得开心 / 一般 / 没兴趣取决于当天脾气、饿不饿、刚玩过没有、是不是它最喜欢的玩具，还会随机发生和房间有关的事（跳上沙发、从木桌上跌下来、撞翻盆栽弄脏地板……）。**留下的乱子**（撒了一地的土、洒了一地的水、掉在地上的书 / 订货目录 / 靠垫、被踩乱的被子）是房间里的东西：`surroundings()` 里看得到、画面上画得出，`tidy()` 或 `clean()` 收拾（5–15 秒一处），盆倒了要先扶起来才能浇水。没人看着的时候团子大约每天闯一次祸（脾气烦躁或饿的时候更多），会出现在「这段时间里」 |

物件可以用编号（`pot#1`）或名字（`绿萝`）指代；背包物品、目录商品、房间里的东西、菜名**都要写全名**。写的东西找不到时不执行，也不猜，而是列出能写的全名：「这里没有「菜地」。这里有：绿萝、菜地1……」「背包里没有「萝卜」。背包里有：萝卜种子×2……」「目录里没有「番茄种」。目录上有：……」「菜谱里没有「煎蛋」。要写菜谱上的菜名：……」。东西在别的房间时说在哪（「「邮箱」在庭院，不在这里。先 goto(庭院)」）。


## 自由活动与平淡的日常（M3）

每天有几段**自由活动时间**（插件配置 `wake.slots`，默认早上 7:30–8:30、中午 11:30–12:30、傍晚 17:30–18:30、晚上 21:30–22:30 之间随机开始，
各 40 分钟）。这段时间由模型决定她做什么。

**睡觉和起床**：她在 23:30–24:00 之间随机的一分钟睡觉（插件配置 `sleep`），在第一段自由活动开始时醒来——所以每天发给她的第一条消息就是早上的自由活动。
睡觉时插件发一条「该睡觉了」，让她睡前用 `diary_read` / `diary_write` / `diary_edit` 整理当天的日记；小屋里她躺到床上（`POST /session {asleep: true}`）。
睡着期间 QQ 消息一律不交给她（自动回 `qq.sleepReply`，同一个聊天半小时最多一次）。

其余时间她**过平淡的日常**，由小屋自己安排（`content.IDLE_ACTIVITIES`）：每小时挑一件（窝在沙发上看书、窗边发呆、
在木桌边喝茶、书架前翻书、睡午觉、树下晒太阳、沙滩散步），走过去做；睡着的时候（插件说了算；没有插件时按 23–7 点）在床上睡觉。
这段时间里她不会饿过「有点饿」（饥饿上限 60）；夜里在床上睡觉。
画面上画的就是她此刻在做的事。下一次自由活动开始时，唤醒消息会说「在这之前，你一直在过平淡的日常——刚才在……」。

### 世界随时间的变化

| 什么 | 规则 |
| --- | --- |
| 她自己 | 饥饿 +5/小时；自由活动以外饥饿最多 60（她自己随便吃点东西） |
| 盆栽 / 菜地 | 水分每天 −30 / −50；下雨时菜地自动浇透 |
| 作物 | 浇过水且在适合的季节时才生长；成熟后产生「成熟了」的消息 |
| 房间 | 每天落灰 +6；猫所在的房间多一些；做饭让厨房 +8 |
| 团子 | 饥饿 +4/小时，到 80 时发出「喵喵叫」的消息；亲密度每天 −2；大约每小时换一个房间 |
| 开拓署 | 每周一 9 点后送基本补给（大米、鸡蛋、猫粮、牛奶）和一封信；新存档有一封欢迎信讲清楚规则 |
| 快递员阿陆 | 每天 9 点后送来已到期的订单；18 点后收走寄售箱并按收购价付贝币；偶尔留一封便条 |
| 小事件 | 大约每两天一件（起雾、海鸥、浮木冲上岸……），进入「你不在的时候」 |
| 沙滩 | 每天约 2 件（雨天 4 件）新东西冲上岸，最多 4 件 |

离开很久时最多补算 14 天。

## HTTP 接口

小屋进程只监听 `127.0.0.1`，启动时把 `{port, token, pid}` 写进 `<状态目录>/house.json`。
除 `/health` 外，所有请求都要带 `X-House-Token`；`Host` 必须是 `127.0.0.1` 或 `localhost`（防 DNS rebinding）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/health` | `{ok, version, pid}`，无需令牌 |
| GET | `/look` | `{ok, text}` |
| GET | `/help` | `{ok, text}` |
| GET | `/events?since=…&actor=resident` | 事件（可按时间、角色过滤，最多 50 条）；唤醒时用来生成「上次醒着的时候，你……」 |
| GET | `/news?since=YYYY-MM-DDTHH:MM:SS` | 这之后「世界自己发生」的事（最多 20 条），用于唤醒时告诉她「你不在的时候」 |
| GET | `/state` | 完整世界状态（JSON） |
| GET | `/status` | `{free, free_until, busy, doing, idle, location}`：是否在自由活动、正在做什么、平时在做什么 |
| GET / POST | `/window` | 查看 / 打开关闭动画窗口：body `{open: bool, scale?: 1-4}`（没有 pygame-ce 时 501） |
| GET | `/screenshot?scale=1\|2` | 当前画面的 PNG（需要 pygame-ce，否则 501），同时存一份到 `world/latest.png` |
| POST | `/do` | body `{script, wait?}` → `{ok, done, id, text, results[]}`：按真实时间执行，最多等 `wait` 秒（默认 900）；没做完时 `done=false`，脚本继续执行 |
| POST | `/report` | body `{id, wait}` → 同上：接着等编号为 `id` 的脚本（插件每次最多等 240 秒，避开 Node fetch 的 5 分钟限制） |
| POST | `/interrupt` | 打断她正在做的事（DSH 中止这一轮时调用） |
| POST | `/session` | body `{free_until}`（epoch 秒；0 = 结束）→ 开始 / 结束自由活动；返回 `before`（她之前在做的日常） |
| POST | `/shutdown` | 存档并退出 |

POST 需要 `Content-Type: application/json`，body 上限 16 KB。

## 文件

`~/.dsh/little-house/`（插件可配置 `stateDir`）：

| 文件 | 内容 |
| --- | --- |
| `world/world.json` | 世界存档 |
| `world/events.jsonl` | 事件日志（追加写），记忆系统的原料 |
| `world/house.json` | 运行中小屋的端口与令牌（退出时删除） |
| `diary/YYYY-MM-DD.md` | 她的日记：每天一个文件（0 点换天），每段标注时间和时段（`### 08:35 · 小屋 · 早上`）。每次自由活动结束前必须写一段（`end_free_time` 在写之前会拒绝）；这是记忆的原料 |
| `plugin.log` | 插件日志（超过 1 MB 轮换为 `.1`） |
| `world/latest.png` | 最近一次截图 |
| `plugin-state.json` | 今天的会话 id（小屋和手机共用）、今明两天投好的自由活动时间（`plans`）、已经结束的时段（`doneSlots`）、上次自由活动开始 / 结束时间 |
| `qq/YYYY-MM-DD.jsonl` | 当天所有 QQ 消息（收到的、她发的），一行一条（`chat`、`name`、`text`、`out`）；记忆的原料 |
| `memory/memory.json` | 她的记忆（唯一来源）；`memory/memory.md` 是给人看的样子；`memory/archive.jsonl` 存所有记过的条目（不会忘） |

## 日记工具

由 `dsh-little-house/diary` 提供。她醒着的时候（自由活动、回消息、睡前）随时能用：

| 工具 | 说明 |
| --- | --- |
| `diary_write(entry)` | 往今天的日记里追加一段（最多 2000 字）；标题是时间和时段（`### 08:35 · 小屋 · 早上`，自由活动以外只有「小屋」） |
| `diary_edit(time, text)` | 改今天某一段（按标题里的时间找）；text 为空就删掉这一段 |
| `diary_read(day?)` | 读某天的日记：今天 / 昨天 / 前天 / YYYY-MM-DD，以前哪天都可以 |
| `end_free_time()` | 结束这次自由活动。这次还没写日记时不结束，提示先 `diary_write`；时间到了她却停着没写日记时，插件会发一句「写下这次的日记，然后 end_free_time」 |
| `end_of_current_operation()` | 自由活动以外接管角色做完事后，把角色交还给日常 |

## 一天一个会话

每天一个「小屋生活 · 日期」会话，0 点换天（`session.rolloverHour`）：**当天的几段自由活动、手机上的 QQ 私聊、睡前整理日记都在这一个会话里**；第二天开新的。
插件发给她的消息都用 `agent.steer`：她空闲时开一轮，正在忙（自由活动做到一半、或在回消息）时在下一步插进去。

- **系统提示词**：人设的第一段（简短版）+ 小屋规则。人设文件里的 `<!-- -->` 注释不给她看。
- **每天的第一条消息**（通常就是早上醒来的那条）开头是：日期、「## 你是谁」（完整人设）、「## 你的记忆」（见下；还没有记忆时退回「日记里最近的一段」），再接着是这条消息本身。
- 日记、QQ 记录、记忆也按同样的「天」划分。

## 手机与 QQ（M5）

她的背包里一直有一部**手机**（`content.PHONE`）：不能吃、卖、摆、喂，`examine(手机)` 能看。QQ（以后还有上网）就是她用这部手机做的事。

插件直接连 NapCat 的 OneBot 11 **WebSocket 服务端**（`qq.url`，正向连接，`plugin/lib/onebot-client.js` + 自带的极简 WebSocket 客户端 `lib/ws-client.js`，不走代理），断线自动重连。

| | |
| --- | --- |
| 谁能找她 | 私聊：`ownerQQ` 和 `friends`（其他人的私聊，QQ 号列在这里才接），她醒着的时候都可以。**群聊暂时关掉**（代码以注释保留在 `qq.js`） |
| 收到的消息 | 进当天的会话：「（手机响了，是 QQ 消息：）主人：……」；自由活动以外，开头告诉她角色此刻在做什么（「11:27，不是自由活动时间。你的角色此刻在客厅，坐在大窗边发呆。手机响了……」）。QQ 表情写成 `[表情:微笑]`，图片写成 `[图片]` 并把图片本身附在消息后（存为 DSH 附件，每条最多 4 张；她看得见），表情包 `[表情包]`。**语音、视频、文件、聊天记录、卡片在桥这里就挡掉**，不发给模型（只记进 QQ 记录）；只有这些内容的消息不会叫她 |
| 她回消息 | 只用 `phone_message(text, photo?, to?)`：text 就是发出去的话（空行分成几条，`[表情:名称]` 变回 QQ 表情，名字不对就原样当文字；去掉 Markdown），`photo` 附一张小屋现在的照片，`to` 不写就是主人。**她直接写的文字不会发出去**。条数不限 |
| 自由活动以外 | 她回消息时可以 `house_do` 看看四周（`surroundings()`、`inventory()`、`help()`：`POST /do {look_only: true}`，马上回答，不打断日常）。**主人请她在屋里做事时**，她直接用 `house_do` 去做：别的动作会让小屋返回 `needs_control`，插件就让她**接过角色的控制权**（小屋进入和自由活动一样的状态，最多 `control.maxMinutes` = 30 分钟），做完她调用 **`end_of_current_operation()`** 把角色交还给日常；忘了调用的话，这一轮结束时或时间到了自动交还。睡前那一轮不能接管 |
| 主动发消息 | 自由活动里写完日记后，`diary_write` 的结果问她要不要给主人发消息（只发有趣、重要的事，流水账不发）。发出的消息就在当天的会话里，不用另外告诉她 |
| 睡着的时候 | 从睡觉到第二天醒来，消息一律不交给她，自动回 `qq.sleepReply`（默认「（睡着了……zzZ）」，同一个聊天半小时最多一次；留空 = 不回） |
| 记录 | 收到的、她发的，都追加到 `qq/日期.jsonl`，给记忆用 |

## 记忆（M4）

**原料**：当天的日记（她自己挑的重要的事）+ 当天的 QQ 记录。不用事件日志。

**整理**：0:10（她已经睡了；以及 DSH 启动时补上还没整理的、最多 7 天），插件开一个「记忆整理 · 日期」会话（preset `little-house-memory`：**不带人设、没有工具**），给它她现有的记忆（带编号）、那天的日记和 QQ 记录，让它只回一个 JSON：

| 字段 | 内容 |
| --- | --- |
| `summary` | 这一天的概括（第一人称，三到五句）→「最近的日子」 |
| `plans` | **想做的事、打算、没做完的事**（日记和聊天里提到的都要列）→「想做的事」 |
| `memories` | 值得长期记住的事（0–5 条，带重要度 1–100）→「记得的事」 |
| `people` | 对认识的人的印象（替换旧的）→「认识的人」 |
| `recalled` / `done` | 这天又想起的旧记忆（重新变清楚）/ 已经做到的「想做的事」（删掉） |

**淡忘**（`plugin/lib/memory.js`，纯代码，不调模型）：按「上次想起」到今天的天数一档一档变：清晰（2 天内）→ 清楚 → 模糊（只剩前六成，「……（记不太清了）」）→ 只剩印象（前十个字）→ 忘记。重要的记得久：重要度 40 的事约 10 天变模糊、40 天忘记；**想做的事忘得快一倍**；重要度 ≥ 90 的永远不会忘（最多模糊）。忘掉的不再给她看，但都留在 `memory/archive.jsonl`。

**使用**：每天会话的第一条消息开头（「## 你的记忆」，四个小节）。整理后的样子也写进 `memory/memory.md`，方便你看。

## 画面

两种方式，同一个渲染器（`house/littlehouse/render.py`，pygame-ce；大部分画面用 LPC 素材，她由 LPC 角色图层拼成再加上鲸鱼的部分，见 `house/littlehouse/assets/lpc/CREDITS.md`；素材文件缺失时退回代码绘制），都在**小屋进程内**：

| 方式 | 什么时候渲染 | 画面 |
| --- | --- | --- |
| 静态「瞥一眼」 | 只在 `house_render` / `GET /screenshot` 时渲染一帧 | 此刻的真实状态：走到一半就画在半路，在灶台边炒菜就有热气 |
| 动画窗口 | 只在窗口打开时（`view.bat`、`POST /window`、配置 `house.window`） | 同上，每一帧都是当时的状态；无人走动时降到 4 fps |

M3 以后动作本身就花真实时间，所以画面不再需要「回放」：`anim.current_pose(world)` 读执行器当前的阶段
（走路就按 1 格 / 秒沿路线插值，做事就画对应的特效），自由活动以外画她正在做的日常（看书、睡觉……）。
灶台上有菜在炖时会一直冒热气。

`house_render` 给模型的是 1280×872 的 PNG（DeepSeek 计约 600 token）。工具说明里提示她本机算力有限、偶尔看一眼即可。
