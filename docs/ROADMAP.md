## M0 里学到的东西（给以后的自己）

- **会话创建**：`ctx.sessionController.create({ sessionId, cwd, agentPreset })` + `resolveAgent(sessionId)`，
  然后 `agent.followup(createUserMessage(...))`。这正是 DSH 自带 schedule 插件的做法，宿主 API 面最小。
- **preset 子插件的工具**在 agent 看来是"继承的"，所以 `tools.restrict({ allow: [] })` 会连自己的工具一起藏掉；
  改用 `restrict({ deny: <全局工具名> })` + `tools.guard()` 白名单。
- `systemPrompt.suppressRuntimeContext()` 能去掉编程向的运行时上下文；`working-directory` 一段是必需的，去不掉（无害）。
- `house_rest` 里调用 `exec.concludeTurn()` 直接结束这一轮，不需要模型再说一句话。
- 会话日志是多帧 zstd（`session.v4.jsonl.zstd`），解压时要跨帧读取。
- M2 实测：DeepSeek-V4.1-Flash 原生支持图片输入（V4-Pro 只支持文本）。工具结果里带图片要先 `attachments.saveImage()`
  再返回 `{ type: 'image', attachment }`。她看完图在小记里写到了「厨房的格子地砖」「雨把海面打出一层细纹」——文字观察里没有这些，
  说明她真的在看图。`defineTool` 的输出 schema 顶层不能写 `required`；这种错误在 inject 回调里会被静默吞掉，
  所以插件现在把日志写到 `plugin.log`。
- M1.5 实测：三次连续唤醒、0 个失败动作。她第一次用寄售箱，在日记里写「感觉像在跟海做买卖」。一开始她同时用 diary_write
  和 house_rest 的 note 写了内容重复的两段，已在工具说明里提示「写过就别重复」。
- M1 实测：唤醒消息里带上「团子饿得喵喵叫；邮箱里来了包裹」后，她先喂猫、再做饭吃，然后取包裹、冒雨种菜、铺地毯、摆贝壳，
  8 步、约 2 万 token（计费输入约 3k）。**把「变化」放进唤醒消息，比让她自己到处查看省得多。**
- 第一次实测时世界描述里写了"院子尽头是沙滩"却没有沙滩这个地点，模型连试两次都失败、浪费行动次数——
  **世界描述里提到的地方必须真的能去**。
